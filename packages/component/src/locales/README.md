# Internationalization (i18n) Guide

This directory contains locale modules for the component package's internationalization system.

## Overview

The component package uses `@lit/localize` for internationalization. All user-facing strings should be wrapped with the `msg()` function or `str` template tag for translation.

## Current Locales

- **Source Locale**: `zh-CN` (Simplified Chinese) - The default development locale
- **Target Locales**: `en-US` (American English)

Additional locales can be added by:
1. Creating a new locale module file (e.g., `ja-JP.ts`)
2. Adding the locale to `targetLocales` in `src/core/i18n.ts`
3. Registering the locale module in the `localeModules` map

## How It Works

### 1. Marking Strings for Translation

Use `msg()` for simple strings and `str` for template literals:

```typescript
import { msg, str } from '@lit/localize';

// Simple string
const greeting = msg('Hello');

// Template literal with variables
const itemCount = msg(str`Found ${count} items`);

// With HTML (use html tag)
const link = msg(html`Click <a href="${url}">here</a>`);
```

### 2. Locale Resolution

The system determines the active locale in this priority:

1. **Host application's `lang` attribute** (`<html lang="...">`)
2. **Persisted preference** in localStorage (`rtc-agent:locale`)
3. **Browser language** (`navigator.language`)
4. **Fallback**: `zh-CN` (source locale)

### 3. Switching Locales

Call `switchLocale()` to change the active locale:

```typescript
import { switchLocale } from './core/i18n.js';

// Switch to English
await switchLocale('en-US');

// Switch to Chinese
await switchLocale('zh-CN');
```

The function automatically:
- Loads the locale module
- Updates `document.documentElement.lang`
- Updates `document.documentElement.dir` for RTL locales
- Persists the preference to localStorage
- Clears formatter caches (numbers, dates, currency)

### 4. Getting Current Locale

```typescript
import { getLocale } from './core/i18n.js';

const currentLocale = getLocale(); // e.g., 'en-US', 'zh-CN'
```

## Locale Module Format

Each locale module exports a `LocaleModule` object:

```typescript
// en-US.ts
import type { LocaleModule } from '@lit/localize';
import { templates } from '../.generated/locales/en-US.js';

const locale: LocaleModule = { templates };
export default locale;
```

The `.generated/locales/` files are auto-generated by `@lit/localize` build tools.

## Translation Workflow

### For Developers

1. **Add new strings** in source code using `msg()` or `str`:

   ```typescript
   const errorMessage = msg('An error occurred');
   ```

2. **Run extraction** to update source locale files:

   ```bash
   pnpm --filter @rtc-agent/component lit-localize extract
   ```

3. **Translate** the extracted strings in `src/locales/zh-CN/`

4. **Build** to generate locale bundles:

   ```bash
   pnpm --filter @rtc-agent/component lit-localize build
   ```

5. **Test** by switching locales in the application

### For Translators

1. Open the locale file in `src/locales/zh-CN/`
2. Find strings with `msgid` (original) and `msgstr` (translation)
3. Provide translations in `msgstr`
4. Run `pnpm lit-localize build` to generate bundles

## RTL (Right-to-Left) Support

The system automatically detects RTL locales (Arabic, Hebrew, Farsi, Urdu) and sets `document.documentElement.dir = 'rtl'`.

To add a new RTL locale:
1. Add the locale prefix to `RTL_LOCALES` in `src/core/i18n.ts`
2. Follow the standard locale addition process

## Number and Date Formatting

All formatting utilities in `src/utils/format.ts` automatically use the current locale:

```typescript
import { formatNumber, formatCurrency, formatFileSize } from './utils/format.js';

formatNumber(1234567.89);     // "1,234,567.89" (en-US) or "1.234.567,89" (de-DE)
formatCurrency(99.99, 'USD'); // "$99.99" (en-US) or "¥99.99" (zh-CN)
formatFileSize(1024);         // "1 KB" (universal units)
```

**Note**: File size units (KB, MB, GB) are kept in English across all locales as they are international standards (IEC 60027-2). See `src/utils/format.ts` for detailed design rationale.

## Testing

Test locale switching in components:

```typescript
import { fixture, html } from '@open-wc/testing';
import { switchLocale } from './core/i18n.js';

test('component renders in English', async () => {
  await switchLocale('en-US');
  const el = await fixture(html`<my-component></my-component>`);
  expect(el.shadowRoot.textContent).to.include('Hello');
});
```

## Best Practices

1. **Always use `msg()`** for user-facing strings, never hardcode
2. **Use template literals** (`str`) for dynamic content, not concatenation
3. **Test both locales** before committing
4. **Keep strings short** and context-independent
5. **Document ambiguous terms** with comments for translators
6. **Avoid nested `msg()` calls** - extract variables first
7. **Use formatter utilities** for numbers, dates, and currency

## Common Issues

### Issue: String not translating

**Solution**: Did you wrap it with `msg()`?

```typescript
// ❌ Wrong
const text = 'Hello';

// ✅ Correct
const text = msg('Hello');
```

### Issue: Build fails after adding new strings

**Solution**: Run extraction and build:

```bash
pnpm lit-localize extract
# Translate new strings
pnpm lit-localize build
```

### Issue: Locale switch doesn't update component

**Solution**: Components must listen to locale changes. Use the `localeController`:

```typescript
import { localeController } from './core/locale-controller.js';

class MyComponent extends LitElement {
  connectedCallback() {
    localeController.host(this);
  }
}
```
