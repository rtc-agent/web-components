这个问题通常和 Lit 组件的生命周期管理有关。让我先分析一下你的代码结构。

可能的原因

  1. 事件监听器未正确清理：disconnectedCallback 里是否正确移除了监听器？
  2. 组件重连时状态丢失：重新插入 DOM 时，connectedCallback 会再次触发，但 @state 的值可能已被重置。
  3. Shadow DOM 未就绪：在 connectedCallback 执行时，Shadow DOM 可能尚未完成渲染。

建议的修复方案

推荐使用 Lit 的 firstUpdated 或 updated 生命周期方法来注册 DOM 依赖的事件，而不是在 connectedCallback 中：

firstUpdated() {
  // Shadow DOM 已就绪，安全地注册事件
  this.addEventListener('keydown', this._onKeydown);
}

disconnectedCallback() {
  super.disconnectedCallback();
  this.removeEventListener('keydown', this._onKeydown);
}

这样可以确保事件注册在 Shadow DOM 渲染完成之后执行。需要我进一步检查具体的代码吗？

推理过程 (3 步)

用户描述的"动态插入后移除再插入"场景，关键在于 disconnectedCallback 中的 removeEventListener 是否传入了正确的函数引用。

如果使用箭头函数直接绑定（如 this.addEventListener('keydown', (e) => {...})），则移除时无法拿到同一引用，导致监听器累积。

正确做法是将处理函数保存为实例字段，如 private _onKeydown = (e) => {...}，确保 add/remove 使用同一引用。

private _onKeydown = (e: KeyboardEvent) => {
  if (e.key === 'Escape') {
    e.stopPropagation();
    this.dispatchEvent(new CustomEvent('rtc-command-panel-close', {
      bubbles: true, composed: true,
    }));
  }
};

✅ 你用了箭头函数字段，引用是稳定的，这部分没问题。

但我发现了另一个潜在问题：e.stopPropagation() 在 Shadow DOM 内默认是不会冒泡到 Light DOM 的。如果你希望在宿主组件中也能拦截这个事件，需要确保事件是 composed: true 的（你这里已经做了）。
